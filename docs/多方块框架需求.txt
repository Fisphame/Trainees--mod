多方块框架需求规格（纯文本，用于筛选现成模组）
来源：Trainees 模组 蓝本 17.1 精练精华网端口 与 化学线反应釜等需求汇总
说明：以下每条都是"要求"，可直接拿去对照候选模组的文档逐条打勾。纯文本，无格式。

一、结构规模与形态

1. 规模。本次不做巨构。最大量级按现有最大的 11x4x11 考虑即可，校验允许一次性全量检查，不需要步进式或分摊到多 tick 的调度。
2. 跨区块。允许结构跨区块，但判定时只认已加载区块：未加载部分视为未成形，绝对不允许为了校验而强制加载区块。
3. 旋转。需要四个水平朝向的旋转（北、南、东、西）。镜像暂不需要。
4. 关键方块。一个结构一个控制器（关键方块），由它发起校验与运行。
5. 成员合法性判据。需要两种：一是精确指定某个方块；二是属于某个方块标签的任意方块。
6. 成员数量约束。需要能表达某类功能方块最多一个、或不限个这样的数量限制。
7. 明确不需要。可视化编辑器、结构轮廓渲染、调试可视化，近期都不做。

二、激活方式

8. 触发方式。右键控制器即可。不需要红石，不需要物品输入，不需要环境条件。
9. 过程。瞬时完成，不需要建造过程或进度条。
10. 运行条件。成形即工作，不需要单独的开机动作。结构被破坏后自动停止。
11. 红石。不需要红石接口。

三、激活后的每 tick 行为

12. tick 主体。控制器驱动：整个结构每 tick 只由控制器跑一次，成员方块不各自 tick。例外是充当搬运算子的方块允许自己 tick，例如总线。
13. 校验频率。结构与网络不需要每 tick 校验，每 20 tick（一秒）复检一次即可；控制器自己的邻居方块变动时立即复检。
14. 网络扫描。需要在控制器处做按需洪泛，收集连通的缓存单元与总线；单次扫描要有访问上限（例如 4096 个方块），超限时给出可上报的截断标记。
15. 性能要求。不高。允许同时存在数十个已成形结构。真正需要的是不会因为玩家乱连线而卡服的上限保护，而不是高吞吐调度。

四、失活与清理

16. 失活条件。结构不完整，包括成员被破坏。
17. 失活延迟。允许最多一秒（20 tick）的延迟；控制器邻居变动时立即触发。
18. 失活动作。清除结构快照与连接关系，容量回落到基础值，停止对外传输，播放失活音效。
19. 内容物。一律不销毁。储存的能量、物品、流体留在控制器或机器自身库存里，不因为失活而掉落或清空。
20. 方块掉落。交给原版破坏逻辑，框架不需要额外掉落物。
21. 客户端同步。需要把成形或未成形、能量、容量、运行状态同步给客户端；用方块更新包与容器数据（ContainerData）同步即可，不需要自定义网络包。

五、状态保存与同步

22. 需要存档。储存的能量、吞吐设置、无线绑定的目标（维度加坐标）。
    说明：允许并推荐机器把运行状态存在自己的方块实体 NBT 里，例如加工进度、开机标志。数据跟着方块走，方块被拆则数据一起消失，天然自愈。
23. 不需要存档。是否成形、网络成员数量、扫描结果。重登后允许最多一秒内重新判定。
24. 区块卸载后。允许结构在区块未加载时视为未成形；区块重新加载后自动恢复判定，不需要额外的持久化激活记录。
25. 明确不要。不要全局激活注册表，也就是不要在 SavedData 里存一张"已成形结构的坐标表"并拿它当作运行依据。成形状态必须永远由当前世界实际方块推导，避免存档与实际不一致。
    需要区分两件事：方块实体自存状态（允许，推荐）与全局激活注册表（不要）。前者随方块消失而消失，后者要自己维护破坏、卸载、回档的一致性。
    可选而且是唯一值得保留的例外：一个只读的统计注册表，只用于不加载区块的全局清单（管理命令、地图集成、全服上限规则）。它只在成形与失活时增删一条记录，绝不参与运行判定。若将来确有这类场景再考虑。
26. 客户端表现。控制器 GUI 显示能量与网络信息；成形与失活播放声音；粒子与轮廓渲染暂不做。

六、配置方式

27. 形状与尺寸。可以写死在代码或注册里，不需要数据包驱动。
28. 成员合法性。需要可改，方块标签即可，方便整合包替换材料。
29. 数值。容量、吞吐、驱动耗这类数值走配置文件（TOML），与形状解耦。

七、其他偏好

30. 不需要可视化编辑器，接受代码 API 加精细控制。
31. 不介意为此引入一个专门的多方块库依赖。
32. 本项目自用，不做公开发布考虑，不需要为第三方整合包作者写文档。

八、现状与迁移约束（若要自研或改造）

33. 现有代码里两套做法并存，本次统一到这一套：每 20 tick 由控制器重算结构，加成形沿（false 到 true 触发一次性动作，true 到 false 做清理）。
34. 现有的一套激活记录存档（把已激活结构的坐标写进主世界存档）要逐步弃用。原因是它不感知成员被破坏、不感知区块卸载，而且管理器是静态单例，跨存档会缓存旧实例。
35. 现有校验代码在取方块状态时没有做区块加载守卫，需要补上：未加载即判定未成形，绝不触发区块加载。
36. 现有结构判定只支持精确方块，需要补上标签判据与数量上下限两类约束。
37. 现有旋转实现只启用了一个固定朝向（北），需要放开为四个水平朝向。
